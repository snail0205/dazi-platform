## 1. 背景与目标

### 1.1 背景
城市青年越来越多地参与需要“凑人”的轻活动（羽毛球、飞盘、徒步、Citywalk、露营拼车等），但现有渠道存在明显摩擦：

- 群聊组局：信息散、难统计人数、谁报名看不清楚、临时鸽子无法约束；
- 平台型产品（闲鱼/小红书）只解决“找人”，不解决“组局的履约与信用”；
- 传统场馆约场平台不解决“人不够”的问题。

### 1.2 产品定位
**一句话定位**：不是社交广场，而是“有场地、有局主、有信用”的轻活动组局工具——让用户 30 秒找到附近正在组局的球局/徒步局，并放心赴约。

### 1.3 产品目标（V1.0）
1. 用户能快速发布/发现/报名一个“局”，核心链路 3 分钟内完成；
2. 通过信用分 + 互评 + 局主机制，将“鸽子率”控制在可接受水平（目标 < 5%）；
3. 平台具备最简商业化闭环：局主发起 AA/收费局，平台按比例抽佣（合规阶段先行灰度）；
4. 一码多端：小程序为主，App/H5 同套代码发布，Web 提供运营与商家后台。

### 1.4 成功指标（北极星与护栏）
| 指标 | 定义 | 目标 |
|---|---|---|
| 周成局数 | 每周“满员且正常开局”的局数 | 上线 6 个月内稳定增长 |
| 报名→成局转化率 | 确认报名且正常出席 / 确认报名 | ≥ 70% |
| 鸽子率 | 爽约人次 / 确认人次 | ≤ 5% |
| 组局搜索时长 | 从打开 App 到提交报名 | ≤ 3 分钟 |

## 2. 术语表

| 术语 | 定义 |
|---|---|
| 局（Activity） | 一次组局活动，含项目、时间、地点、名额、费用等 |
| 局主（Host） | 发起并管理某次局的人 |
| 搭子 / 局友（Member） | 报名并参加局的用户（用户与局主可同账号切换） |
| 鸽子（No-show） | 已确认但未出席且未提前取消的行为 |
| 候补（Waitlist） | 名额已满时的排队报名，空位按序补入 |
| 信用分（Credit Score） | 用户履约信用的数值化表达，影响报名权与功能权限 |
| 拼车 / 拼装备 | 报名时可选的附加拼单需求（V1.1+） |
| 局主等级 | 局主历史履约/好评累积的成长等级，决定可组局规模上限与费率 |

## 3. 用户角色与多端映射

| 角色 | 使用端 | 说明 |
|---|---|---|
| 游客 | 小程序 | 仅浏览/分享，不可报名（需登录） |
| 用户（搭子） | 小程序 / App / H5 | 浏览、搜索、报名、候补、取消、评价、发起局 |
| 局主 | 小程序 / App | 用户身份的子集：发布局、管理名单、收款、点名 |
| 运营（Operator） | Web 后台 | 内容审核、举报处理、类目管理、数据看板 |
| 场地商家（预留） | Web / 商家小程序 | 发布空闲时段、承接局场地订单、核销 |
| 平台管理员 | Web 后台 | RBAC、配置、财务对账、风控 |

> 设计原则：C 端（找局、报名、管理）只做一套 uni-app 代码；Web 端只做运营/商家/管理后台，避免同页面重复实现。

---

## 4. 差异化功能（USP，评审聚焦点）

1. **信用履约闭环**：报名冻结信用门槛 → 开局前提醒 → 鸽判定 → 扣分/申诉 → 等级恢复，全链路规则引擎；
2. **局主经济**：局主可组收费局、AA 收款、设押金，平台抽佣费率与局主等级挂钩；
3. **人-场联动（预留）**：场地商家空闲时段可直接被局主认领，形成“组局即订场”；
4. **AI 匹配合适的局（V2）**：按运动水平、时间窗、通勤距离做推荐。

## 7. 功能需求详述

> 优先级定义：**P0** = V1.0 必须有；**P1** = V1.1；**P2** = V2.0。
> 每条验收标准（AC）以“Given/When/Then”可测为准。

### 7.1 账号与登录
| 编号 | 需求 | 优先级 |
|---|---|---|
| REQ-101 | 支持微信小程序一键登录（code2session）并自动注册；游客可浏览不可报名 | P0 |
| REQ-102 | 支持绑定手机号（用于找回与风控）；同一用户多端（小程序/App）身份打通 | P0 |
| REQ-103 | 用户须勾选《用户协议》《隐私政策》《免责声明》后方可报名/发布 | P0 |

AC-101：新用户首次报名前必须完成登录；登录后跳回原页面并保留填写内容。

|---|---|---|
| REQ-301 | 局主发布必填：项目类目、标题、简介、开始/结束时间、地点（地图选点+文字）、名额上限、费用模式（免费/AA/定额/押金制） | P0 |

### 7.6 报名 / 候补 / 取消（名额一致性是本模块核心）
| 编号 | 需求 | 优先级 |
|---|---|---|
| REQ-601 | 报名即占位；收费局需在 15 分钟内完成支付，超时释放名额并通知候补第 1 位 | P0 |
| REQ-602 | 名额扣减使用 Redis 原子操作 + 数据库乐观锁兜底，杜绝超卖 | P0 |
| REQ-603 | 免费局开局前 N 小时（默认 4h，局主可设）取消不扣分；之后取消记“临时取消”轻扣分 | P0 |
| REQ-604 | 收费局退款规则：开局前 ≥24h 全额退、4–24h 退 50%、<4h 不退（局主可自定义并在详情页明示） | P0 |
| REQ-605 | 满员自动进入候补队列，有人取消按序补入并推送；候补期间可随时退出 | P0 |
| REQ-606 | 同一用户同一时段（重叠 30min 内）最多报名 1 个收费局，防止“占坑比价” | P1 |
| REQ-607 | 信用分低于阈值（< 60）或处于“冻结报名期”时不可报名/候补 | P0 |

AC-602：100 人并发报名 10 个名额的局，最终确认人数必须精确等于 10。
AC-605：候补补位按队列 FIFO，且补位后超过 15 分钟未支付自动释放给下一位。

## 8. 核心状态机

### 8.1 局状态
```
DRAFT(草稿) → PENDING_AUDIT(待审核) → OPEN(报名中) ⇄ FULL(已满,可开候补)
                                        → IN_PROGRESS(进行中) → ENDED(已结束)
PENDING_AUDIT/OPEN/FULL → CANCELLED(已取消, 需全员退款/通知)
PENDING_AUDIT → REJECTED(驳回)
```
- 自动流转：开始时间到 → IN_PROGRESS；结束时间过 24h → ENDED。
- CANCELLED 后：收费局自动全额退款、候补清空、通知全员。

### 8.2 报名状态
```
PENDING_PAY(待支付, 15min) → CONFIRMED(已确认) → ATTENDED(已到场) / NO_SHOW(爽约)
CONFIRMED → CANCELLED(已取消, 按规则退款/扣分)
FULL 时: WAITLIST(候补) → CONFIRMED(补位) / WAITLIST_CANCELLED(退出候补)
```

### 8.3 订单状态
```
CREATED → PAID → SUCCESS / REFUNDED / PARTIAL_REFUNDED / FAILED
PAID + 押金制: HELD(冻结) → RELEASED(到场解冻) / REFUNDED
```

## 11. 埋点与指标体系

**技术埋点**：接口耗时、报名抢位冲突率、退款率、申诉裁决分布、WebSocket 在线率。

## 13. 技术实现建议（与选题一致）

```
[小程序/App/H5] uni-app(Vue3+TS)+Pinia+uView-plus
        │ HTTP / WSS
[Web 运营后台]  Vue3 + Vite + TS + Element Plus
        │
[Nginx / API Gateway]
        │
[Spring Boot 3]  Sa-Token(或Spring Security)+JWT
   ├─ 模块：auth / user / activity / booking / payment / credit /
   │        chat / audit / admin / merchant(预留)
   ├─ MySQL 8（业务库 + 分账对账库）  Redis（GEO/名额锁/队列/缓存）
   └─ 中间件：WebSocket(局内聊天) · 定时任务(开局提醒/超时释放/月结)
[对象存储 OSS] 头像/图片 ·  [消息服务] 微信订阅消息 · 厂商推送(V1.1)
```
重点设计点：
1. 名额扣减：`Redis Lua` 原子占位 + 数据库唯一约束/行锁兜底；
2. 附近检索：Redis GEO（小规模）或 MySQL 空间索引（规模后）；城市级分表准备；
3. 支付分账：商户平台开通服务商分账，落“分账明细表”可对账；
4. 信用规则引擎：扣分/恢复/冻结全部配置化 + `credit_log` 全流水；
5. 审核与风控：文本/图片审核 API + 本地敏感词 + 操作审计。

## 15. 风险与开放问题

| 1 | 平台卷入线下人身纠纷 | 免责声明 + 高风险项目强制须知；保留紧急联系人字段；不承诺保险（可对接第三方活动险，V1.1 评估） |
